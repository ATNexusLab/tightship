# Render dist/cursor pieces and manifest

## Context

Business rules 2, 3, 8, and 11 — spec: `docs/specs/cursor-plugin/ship-for-cursor.md`

## Scope

- `xtask/src/build/cursor.rs` and the `cursor` arm in `xtask/src/build.rs` (multi-harness render, staging under `dist/.cursor.tmp` → `dist/cursor/`).
- Built tree through manifest, skills, commands, and agents (not `contract/` or `hooks/hooks.json` — those are #69).
- `dist/cursor/agents/adversarial-verifier.md` with `readonly: true` in front matter (rule 8; Cursor does not enforce read-only).
- `dist/cursor/bin/tightship`, `tightship.cmd`, and the four platform binaries, with `harnesses/cursor/launcher-env.*` joined like other harnesses.
- `xtask/tests/build.rs` (and fixtures) for slash commands, neutrality, and manifest `variables` from `content/options.toml`.

Epic #59 already added shared build staging and installers; this task only adds the Cursor renderer output.

## Acceptance criterion

Scenarios 1 and 7

### Scenario 1 — Build both harnesses (happy path)

```gherkin
Given content/ and harnesses/claude-code/ and harnesses/cursor/ are valid
When the maintainer runs cargo xtask build
Then dist/claude-code/ and dist/cursor/ exist
And dist/cursor/commands/spec.md holds a rendered /spec reference
And dist/cursor/skills/grilling/SKILL.md holds no Claude Code literal
```

### Scenario 7 — Verifier dispatches (FR-VER-01)

```gherkin
Given tightship is installed in Cursor
When the adopter invokes adversarial-verifier through Task
Then the subagent runs with the shipped prompt
```

Automated gate for this scenario: build tests assert `dist/cursor/agents/adversarial-verifier.md` exists with `readonly: true` and rendered prompt. Interactive Task dispatch is covered in the release checklist (#75).

## Possible impacts

Build success line lists both harnesses; Claude Code and Antigravity CLI render paths unchanged.

1. `cargo xtask build`
2. `cargo test --package xtask build`
3. Inspect `dist/cursor/.cursor-plugin/plugin.json` and `agents/adversarial-verifier.md`
