# Options file and tightship options subcommands

## Context

Business rule 5 — spec: `docs/specs/cursor-plugin/ship-for-cursor.md`

## Scope

- `$HOME/.cursor/tightship/options.json` as the only Cursor option store (rule 6). Hooks and the binary read
  it through `tightship/src/options.rs` (`cursor_options_path`, `cursor_boolean`); extend that module — do
  not add `tightship/src/options/` as a directory.
- New `tightship options` subcommands in `tightship/src/main.rs`: `set`, `list`, `reset` with the messages
  and exit codes in the spec Errors table (`OPTIONS_UNKNOWN`, `OPTIONS_INVALID_VALUE`, `OPTIONS_IO`).
- Hook option guards in the **built** `dist/cursor/hooks/hooks.json` (PowerShell reads `options.json`, not
  `CLAUDE_PLUGIN_OPTION_*`), coordinated with #69 so contract and memory hooks respect `contract` and
  `memory`.
- **Out of this task:** `${TIGHTSHIP_DATA}/options.toml` for Antigravity CLI (#63). Cursor does not use that
  path.

Manifest `variables` for Configure are rendered in #68; this task only ensures runtime reads match the install
guide.

## Acceptance criterion

Scenarios 4, 8, 9, and 10

### Scenario 4 — Memory off (FR-CTR-03.1)

```gherkin
Given options.json has "memory": false
When sessionStart and beforeSubmitPrompt hooks run
Then no vault text is injected
And contract parts omit vault rules
```

### Scenario 8 — Option off leaves no contract text (FR-CTR-02.1)

```gherkin
Given options.json has "contract": false
When a new conversation starts
Then the agent's context holds no rule of the contract
```

### Scenario 9 — Set an option (FR-INS-04.1, happy path)

```gherkin
Given options.json does not exist
When the adopter runs tightship options set memory false
Then stdout is "Set memory to false."
And options.json holds "memory": false
```

### Scenario 10 — Unknown option (exception)

```gherkin
When the adopter runs tightship options set not_an_option true
Then stderr is "error: unknown option \"not_an_option\""
And the exit code is 1
```

Scenarios 4 and 8 need hook JSON from #69; this task owns the file format, CLI, and guards that make them
true.

## Possible impacts

`docs/data-model/options.md` documents `options.json`; update if CLI surface changes. `tightship/tests/` gains
options coverage with a temp `HOME`.

## How to test

1. `cargo test -p tightship` (options subcommands and `cursor_boolean` against a temp directory)
2. With `dist/cursor` built (#68) and hooks from #69: set `memory` / `contract` false and run hook commands
   or integration fixtures
3. `tightship options set not_an_option true` → exit 1 and stderr per scenario 10
