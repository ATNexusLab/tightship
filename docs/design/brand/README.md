# Brand

## The name

A tight ship is a deploy that leaves strapped down. Every change carries its issue, its spec, green gates,
and a verified claim of done before it ships. The workflow covers software engineering end to end, from
the first requirement to the release.

The direction is called Manifest: freight paperwork. Every shipment has a label, a list of what it holds,
and a tie that keeps it closed.

## Voice

Short. Imperative. Concrete.

- Say what happens, in the fewest words that stay exact: "No issue, no work."
- Name the real thing: the gate, the command, the requirement ID. Never "seamless", "powerful", or
  "effortless".
- State limits plainly. A pre-release says so on the first screen.
- Taglines and headings in the banner are set in capitals. Running text is sentence case.

| Use | Avoid |
| --- | --- |
| Gates green or it doesn't ship. | A powerful way to ensure quality across your workflow. |
| Every change has an issue. | Effortlessly track all your changes. |
| Release is a decision, not a step. | Streamline your release process. |

The tagline is **Ship it tied down.**

## The mark

![The tightship mark](logo.svg)

A shipping tag in safety orange. The eyelet is reinforced and the string runs through it: the shipment is
tied. The three bars are its manifest.

- It reads on light and dark backgrounds without a tile, so one file serves both.
- Keep clear space of a quarter of its height on every side.
- Never recolor it, rotate it, or put it on orange.
